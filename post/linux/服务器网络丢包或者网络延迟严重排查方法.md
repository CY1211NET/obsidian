# 一、先确认问题：到底是丢包还是延迟

### 1️⃣ 基础检测

```bash
ping -c 10 8.8.8.8
```

关注：

- `packet loss`（是否丢包）
    
- `time=xx ms`（延迟）
    
- `mdev`（波动）
    

👉 判断：

- 丢包：> 0% 就异常
    
- 延迟：看你业务，一般 >100ms 就要注意
    

---

# 二、定位在哪一层出问题

## 2️⃣ 本机网络栈 vs 外部网络

```bash
ping 127.0.0.1
```

👉 如果这里都有问题 → 系统/CPU/内核问题

```bash
ping 网关IP
```

👉 如果这里就丢包 → 局域网/网卡问题

```bash
ping 公网IP（如 8.8.8.8）
```

👉 如果这里才出问题 → 外网问题

---

# 三、链路追踪（核心工具）

## 3️⃣ 路由分析

```bash
traceroute 8.8.8.8
```

或更强：

```bash
mtr 8.8.8.8
```

👉 看哪一跳开始：

- 延迟突然升高
    
- 丢包开始出现
    

👉 结论：

- 第一跳问题 → 本机/网关
    
- 中间某跳 → 运营商问题
    
- 最后一跳 → 目标服务器问题
    

---

# 四、检查网卡（最容易被忽略）

## 4️⃣ 查看错误包

```bash
ifconfig
```

或

```bash
ip -s link
```

重点看：

- `RX errors`
    
- `TX errors`
    
- `dropped`
    

👉 如果这些增长：

- 网卡驱动问题
    
- 硬件问题
    
- 带宽打满
    

---

## 5️⃣ 查看带宽是否打满

```bash
iftop
```

或

```bash
nload
```

👉 如果带宽跑满：

- 限速
    
- 查异常流量
    

---

# 五、系统性能瓶颈

## 6️⃣ CPU 是否打满

```bash
top
```

👉 CPU 100%：

- 网络处理不过来
    
- 软中断过高（softirq）
    

---

## 7️⃣ 网络中断压力

```bash
cat /proc/interrupts
```

👉 某个 CPU 飙高：

- 网卡中断不均衡（需要 irqbalance）
    

---

## 8️⃣ socket 队列积压

```bash
netstat -s
```

重点看：

- `packet receive errors`
    
- `listen queue overflow`
    

---

# 六、TCP 层问题（进阶）

## 9️⃣ 查看重传

```bash
ss -s
```

👉 如果 `retrans` 很高：

- 网络质量差
    
- 丢包严重
    

---

## 🔟 抓包分析（终极手段）

```bash
tcpdump -i eth0
```

👉 可以看到：

- 重传
    
- 丢包
    
- 延迟 ACK
    

---

# 七、DNS 问题（很多人忽略）

```bash
nslookup google.com
```

👉 DNS 慢 ≠ 网络慢  
很多“卡”其实是 DNS 解析慢

---

# 八、云服务器特殊问题（你很可能会遇到）

如果你在云上（AWS / 阿里云）：

👉 常见问题：

- 安全组限速
    
- 带宽封顶
    
- 邻居 noisy neighbor
    

---

# 九、快速定位口诀



```
本机 → 网卡 → 网关 → 路由 → 带宽 → CPU → TCP → 抓包
```

---

# 十、总结



> 1. 先用 ping 判断是否丢包和延迟
>     
> 2. 用 traceroute/mtr 定位问题链路
>     
> 3. 检查网卡是否有丢包（ip -s link）
>     
> 4. 查看带宽是否打满（iftop）
>     
> 5. 检查 CPU 和软中断
>     
> 6. 查看 TCP 重传（ss -s）
>     
> 7. 最后用 tcpdump 抓包分析
>
